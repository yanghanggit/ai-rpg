# 上下文窗口管理（Context Window Management）

## 意图

角色与场景的 agent 记忆随回合单调累积，上行 prompt 持续膨胀，最终逼近模型上下文上限。系统用三种手段应对：写入精简提示词与战斗记忆归档是「减量」，上下文占比度量是「探针」——前者压低历史体积，后者量化当前窗口占用，为将来触发压缩提供信号（目前仅采集，尚未接入消费点）。

## 精简提示词

`DeepSeekClient` 同时持有「发送给 LLM 的完整提示词」与「写入记忆的精简提示词」两个版本：上行请求用完整版，写回记忆用精简版，从而让后续轮次不再携带完整提示词；完整版仅作为消息附加字段留痕。

当前消费方是 `StageDescriptionSystem`（场景描述）与 `MonsterPrePlaySystem`（怪物出牌决策），二者都在批量调用后把精简版写入各自 agent 记忆。

## 战斗记忆归档

`CombatArchiveSystem` 在战斗结束后触发：定位「战斗开始」与「战斗结束」两条标记消息，删除二者之间的整段逐条记录，改由 LLM 生成一段第一人称摘要，作为角色对这场战斗的唯一记忆；被删除的原文附在摘要消息上留痕。

## 上下文占比度量

`DeepSeekClient` 在每次响应后解析 token 用量，计算其占模型上下文窗口的比例，作为「该 agent 上下文有多满」的信号。该值随 AI 回复消息一并写入记忆，并同步到 `AgentMemory` 供后续读取；经存档持久化、恢复时回填，跨命令可读。当前无任何系统据此触发压缩，属纯采集状态。
