# 战斗管道（Combat Pipeline）

---

## 定位

战斗管道是副本模式下驱动战斗全生命周期的 ECS 处理器链。管道以单次 `process()` 为心跳——系统按注册顺序线性执行，顺序即因果链，无事件总线、无中心化状态机。

系统按四类阶段自守卫推进：仅首次（初始化）、循环（抽牌-决策-执行-仲裁-结算）、仅末次（归档清理）、始终（入场/收尾）。每个系统检查组件与战斗状态自行决定是否执行，管道本身不分叉。

---

## 设计决策

### 牌库预置，抽牌堆确定性填充

初始牌库不再由 LLM 现场生成，而是由角色蓝图预置卡牌直接写入 `DeckComponent`。`FillDrawPileSystem` 在初始化时深拷贝预置牌、按角色攻击/防御对伤害与格挡做加法叠加后洗牌填入 `DrawPileComponent`，全程零 LLM。设计意图：牌库内容回归内容作者的确定性控制，战斗起始不依赖 LLM 生成质量；属性叠加让同一张预置牌在不同角色身上呈现差异化强度，牌本身保持稳定、可复现。

### 仲裁的三方归属

仲裁（由 LLM 结算数值与演出叙事）按触发时机归属不同主体，而非统一由场景实体处理：

- **出牌仲裁**由场景实体（stage entity）执行。它持有战场环境叙事与各角色 HP 变化通知，能产出叙事一致的结算结果；仲裁读入卡牌叙事文本作为演出种子，伤害仍按确定性规则结算，叙事只影响演出措辞。
- **回合末词缀仲裁**由持卡人（pass turn 的行动者）执行，只结算其手牌中带回合末词缀的牌，结果定向广播给受影响角色。归属持卡人而非场景实体的原因：词缀是持有者自身的持续状态，结算视角应落在持有者。
- **消耗品仲裁**由世界实体「世界.消耗品仲裁」作为临时 agent 执行，结算上下文不写回宿主记忆。

→ 参见：[卡牌数据模型（Card）](card.md)、[消耗品系统（ConsumableItem）](consumable-item.md)

### 仲裁数值来源唯一性

仲裁结算的数值以系统给出的角色状态为唯一来源：防御值（DEF）已聚合完成（基础防御 + 手牌 block 之和），LLM 必须直接采用，不得再叠加任何手牌 block，也不得从对话历史或前几回合广播中补算卡牌与数值。该约束用于阻断 LLM 把历史回合出现过、当前并不持有的卡牌误植回本次结算，造成伤害计算错误。

### 决策与结算分离

出牌分两步：先决策（选牌选目标），再仲裁（算伤害算效果）。怪物的决策由 `MonsterPrePlaySystem` 用角色自身 LLM 记忆并行完成，产出确定性的出牌动作；玩家决策来自 TUI 输入，`PartyPrePlaySystem` 是与怪物侧对齐结构的预留 hook。分离后决策可并行（多个怪物同时思考），仲裁保持单线程（叙事一致），且决策 LLM 不受仲裁风格干扰。

一次怪物行动触发只产出一张牌决策：选一张牌或过牌，不存在一次连打多张的语义。怪物决策采用「提示词预防 + 决策兜底」双层防护——提示词只暴露费用可支付（cost ≤ 剩余能量）的牌并引导能量不足时过牌；即便仍选错，也在生成出牌动作前拦截，向怪物记忆写入无效提醒并强制过牌，保证错误决策不进入结算、不破坏回合状态机。

### 回合行动序列

回合按角色创建顺序（creation_order）排列行动顺序，确定性且可复现。回合完成的标志是所有存活角色均已 pass turn，与 energy 是否耗尽无关（耗尽仅限制能打出的牌数，不自动 pass）。

## 阶段划分

### 初始化

`CombatInitActorSystem` 为参战角色挂载空牌堆、注入战场环境并挂载填充动作；`CombatInitStageSystem` 切换战斗状态为进行中。随后 `FillDrawPileSystem` 以预置牌确定性填充抽牌堆，取代原 LLM 牌库生成。

### 回合循环

抽牌（含 retain 牌取回与弃牌堆洗牌回补）→ 出牌决策（怪物并行 LLM，玩家 TUI）→ 动作执行（出牌、传递、使用消耗品、装备转化）→ 仲裁（出牌、消耗品、回合末词缀）→ 死亡判定 → 场景塞牌评估 → 回合完成判定 → 回合清理 → 胜负判定 → 新回合创建。循环的每一轮即一次 `process()` 心跳。

### 回合末

回合完成判定（所有存活角色 pass turn）后清理旧手牌：非 retain 牌进弃牌堆，retain 牌入保留队列下回合优先取回。胜负判定是终局分支点：一旦分出胜负，直接跳至战斗后处理。

### 战斗后

`CombatLootSystem` 按怪物推理掉落（基础掉落 + 部位破坏额外掉落）。`CombatArchiveSystem` 生成第一人称战斗摘要、压缩历史、触发记忆存储。`CombatPileTeardownSystem` 清空三堆牌副本、归还由装备临时转化而来的装备，`DeckComponent` 原始牌库完整保留。

## 跨系统关系

- **副本生成管道**产出 `CombatRoom`（stage + actors + 预置卡牌），战斗管道消费它 → 参见：[副本生成管道](dungeon-generation.md)
- **装备系统**将装备转化为临时手牌参与出牌，与普通卡牌共用出牌仲裁结算 → 参见：[装备系统](gear-item.md)
- **消耗品系统**走独立的世界实体临时 agent 仲裁 → 参见：[消耗品系统](consumable-item.md)
- 战斗结束后 `CombatArchiveSystem` 触发记忆存储，衔接家园模式的叙事连续性
