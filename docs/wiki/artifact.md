# 神器（Artifact）

---

## 定位

神器是内容作者书写的**场景级战斗修正规则**载体。它不是角色物品：不进背包、不进牌堆、不物化为卡牌；它只回答一个问题——发生在这个场景里的出牌/消耗品仲裁之后，额外还要遵守什么。引擎对神器内容保持无感知，只在仲裁后把它交给**神器仲裁临时 agent** 自行理解与执行。

## 构成与挂载

神器由叙事身份（名称、描述）与一组修正规则组成；规则是自然语言的指导性文本，以列表承载、为多条叠加预留空间。规则只写世界观内可执行的指导语义，不写运行时工具或字段——内容作者不接触引擎视角。

当前神器数据**硬编码**在 `ArtifactArbitrationSystem` 的 `_HARDCODED_ARTIFACTS` 常量中（数据注入方案待定）。

## 仲裁时如何生效

出牌/消耗品仲裁由各自系统先完成一次结算。随后 `ArtifactArbitrationSystem` 响应 `PlayCardsAction` / `UseConsumableItemAction`，借世界实体「世界.神器仲裁」（`ArtifactComponent` 标记）作为**隔离的临时 agent**：

1. 注入当前回合数、场景神器修正规则、场上存活阵营、场景环境快照；
2. 临时 agent 依规则判定是否触发（如「第 2 回合」）并调用 `set_entity_hp` 覆盖式写入最终 HP；
3. 提交仲裁结果（战斗日志/叙事），落库并广播。

> 权限边界：神器仲裁者不是场景本身，无权改写场景环境快照（`StageDescriptionComponent`）。它只把「发生了什么」写入场景实体记忆，由场景在后续自身推理（如出牌仲裁）中自行更新环境快照。

因此「第 N 回合队伍方全员倒下」「怪物伤害翻倍」这类场景规则以内容数据存在，不改引擎。临时 agent 的对话上下文仅在本次结算中累积，结束后不写回宿主世界实体持久记忆。

## 设计意图

- 机制与内容分离：场景规则是数据，不是硬编码进仲裁系统的分支。
- 借重 LLM 的灵活性：规则由临时 agent 在运行时按需发现并解释，而非系统预先筛选注入，保留内容表达的空间。
- 场景级而非卡牌级：神器规则对该场景内所有出牌/消耗品仲裁生效，是背景约束；卡牌词缀则属于单次出牌/受击结算。
