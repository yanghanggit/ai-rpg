# 战斗管道（Combat Pipeline）

---

## 定位

战斗管道是副本模式下驱动战斗全生命周期的 ECS 处理器链。系统按注册顺序线性执行，顺序即因果链，无事件总线、无中心化状态机；各系统检查组件与战斗状态自行决定是否执行，按「仅首次 / 循环 / 仅末次 / 始终」四类阶段自守卫推进。

## 设计决策

### 牌库预置，抽牌堆确定性填充

初始牌库由角色蓝图预置卡牌直接写入 `DeckComponent`，战斗起始不调用 LLM；抽牌堆按角色攻击/防御对伤害与格挡做叠加后确定性填充。意图：牌库内容回归内容作者的确定性控制；属性叠加使同一张预置牌在不同角色身上呈现差异化强度。

### 仲裁的三方归属

仲裁按触发时机归属不同主体，而非统一由场景实体处理：

- 出牌仲裁由场景实体执行：它持有战场环境叙事与各角色 HP 变化通知，能产出叙事一致的结果；叙事只影响演出措辞，伤害仍按确定性规则结算。
- 回合结束词缀仲裁由持卡人执行，只结算其手牌中带回合结束词缀的牌，结果定向广播给受影响角色。归属持卡人而非场景实体：词缀是持有者自身的持续状态，结算视角应落在持有者。
- 消耗品仲裁由世界实体「世界.消耗品仲裁」作为临时 agent 执行，结算上下文不写回宿主记忆。

→ 参见：[卡牌数据模型（Card）](card.md)、[消耗品系统（ConsumableItem）](consumable-item.md)

### 仲裁数值来源唯一性

仲裁结算的数值以系统给出的角色状态为唯一来源：防御值已聚合完成（基础防御 + 手牌格挡之和），LLM 必须直接采用，不得再叠加手牌格挡，也不得从对话历史或前几回合广播中补算卡牌与数值。该约束用于阻断 LLM 把历史回合出现过、当前并不持有的卡牌误植回本次结算。

### 决策与结算分离

出牌分决策与仲裁两步：决策并行（各行动者同时选牌选目标），仲裁单线程（叙事一致），决策 LLM 不受仲裁风格干扰。怪物决策由 `MonsterPrePlaySystem` 用角色自身记忆完成，`PartyPrePlaySystem` 与怪物侧对齐结构。

一次怪物行动只产出一张牌决策（选一张牌或过牌），不存在连打多张。怪物决策采用「提示词预防 + 决策兜底」双层防护：只暴露费用可支付的牌并引导能量不足时过牌；即便选错，也在生成出牌动作前拦截、强制过牌，保证错误决策不进入结算。

### 回合行动序列

回合按角色创建顺序排列行动顺序，确定性且可复现。回合完成的标志是所有存活角色均已 pass turn，与 energy 是否耗尽无关（耗尽仅限制能打出的牌数，不自动 pass）。

## 生命周期

### 回合循环

抽牌 → 出牌决策 → 动作执行（出牌、可传递牌转移、使用消耗品、装备物化）→ 仲裁（出牌、消耗品、回合结束词缀）→ 死亡判定 → 回合完成 → 清理 → 胜负判定 → 新回合。循环的每一轮即一次 `process()` 心跳。

### 回合末

所有存活角色 pass turn 后清理旧手牌：非 retain 牌进弃牌堆，retain 牌入保留队列下回合优先取回并占用下回合手牌名额（手牌按目标张数补齐）。

### 战斗后

`CombatLootSystem` 按怪物推理掉落（基础掉落 + 部位破坏额外掉落）；`CombatArchiveSystem` 生成战斗摘要并触发记忆存储；`CombatPileTeardownSystem` 清空三堆牌副本、归还装备，`DeckComponent` 原始牌库完整保留。

## 跨系统关系

- 副本生成管道产出 `CombatRoom`（stage + actors + 预置卡牌），战斗管道消费它 → 参见：[副本生成管道](dungeon-generation.md)
- 装备系统将装备物化为临时手牌参与出牌，与普通卡牌共用出牌仲裁 → 参见：[装备系统](gear-item.md)
- 消耗品系统走独立的世界实体临时 agent 仲裁 → 参见：[消耗品系统](consumable-item.md)
- 战斗结束后 `CombatArchiveSystem` 触发记忆存储，衔接家园模式的叙事连续性
