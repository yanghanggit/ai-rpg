# 卡牌设计指南（Card Design）

---

## 定位

面向内容作者，回答「**每个字段这样设计，可以被怎样玩**」——即设计方法论，而非字段定义或具体范例的副本。

为避免同一事实出现两处、日后还要裁决谁权威，本文**不复述**以下内容，只给原则与指向：

- 字段语义（每个字段是什么）→ [卡牌数据模型（Card）](card.md)
- 词缀格式与约束（怎样写才合法）→ 见下文「生成契约」（`card_design` 引擎的 `submit_card` 工具 schema）
- 具体组合范例（原型长什么样）→ `demo/card_skeletons.py`（骨架）与 `demo/card_prototypes.py`（原型类型 + 含教学元数据的注册表）
- 三端归类 → [三端化思维（Combat Ports）](combat-ports.md)

## 设计总原则

- 每个字段单一职责，玩法靠**组合**表达，不靠新增字段。
- **机制与故事分层**：原型 / 骨架只描述 DBG 机制，与具体故事内容无关；具体意象、命名风格与用词偏好由生成者（Actor / World）自己的设定与历史决定。引擎提示词只给任务与契约，不预设审美。取材边界的判据（通用指代 vs 具体实例、场景销毁后的引用完整性）见 [角色自持内容生成（Actor Intrinsic Generation）](actor-intrinsic-generation.md)。
- **卡是「被解释成战斗资源」的表现层，不是动作**：不必把设计锚定在「招式」上，否则只剩动词、窄化题材。
- **基础牌（tier=basic）是保底而非候选**：攻击 / 防守这类开局保底牌统一命名、无词缀、不进入选型池；同一持卡者的多张基础副本共用一个名字，避免各自取名/加词缀后难以扫读。
- **确定性骨架 + 语义词缀**：确定性字段让回合循环可运转，词缀提供自由规则；接受仲裁 LLM 解释带来的语义 / 数值偏差。
- 同一张牌有**两个身份**同时成立：作为手牌的「持有状态」与作为行动的「打出」。
- 原型是**引导**不是模板：原型固定定量骨架并给出方向，具体规则由角色 agent 实例化，一个原型可覆盖多个方向。

## 硬约束（字段组合）

字段并非都能自由组合，以下规则在生成与手写内容中都必须遵守：

- `retain` 与 `ethereal` 互斥：二者同属「回合边界手中牌去向」这一语义轴的两极，同开会令 ethereal 先生效、retain 沦为死开关。
- `transferable` 与 `exhaust` 设 true 的前提是 `playable=true`：牌不可出时二者永不触发，属无效组合。
- `SPREAD` 与 `transferable` 同开**允许**（模型与结算都支持），但它有乘法性质：`hit_count` 既决定「发几份副本」又决定「每份打出时打几段」，同一目标被命中 k 次即得 k 份、每份再独立打出，而 `SPREAD` 的命中是纯随机，故期望收益与方差都高。定价时按此对待；能量（每份都要付 `cost`）是唯一闸门。
- `transferable` **只传一跳**：副本落地到目标手牌时系统把其 `transferable` 置为 false，收到副本者不能再次转手；自传递复制拿回的副本同样不可再传。副本保留原 `source` 与词缀，持续结算不受影响。副本数 = 该角色在解析目标列表中的**出现次数**（与 `SPREAD` 的命中分配一致：一击一份，命中是纯随机、可重复命中同一人），`SINGLE` / `ALL` / `SELF` 则各拿一份。
- `target_type=SELF` 可与 `transferable` 同开（**模型层允许**）：`SELF` 解析出的目标即出牌者本人，`transferable` 会把副本复制回自己手牌，即「自传递复制」。

## 字段速览

只给「设计含义」；取值语义见卡牌数据模型。

**资源与节奏**

- `cost`：出牌门槛，决定节奏与「出还是过」的取舍；只在出牌时刻收门槛，不影响能否留手。低费=稳定可循环，高费=爆发 / 终结。
- `damage` / `hit_count`：输出的强度与形态；`damage=0` 时价值改由 `block` 或词缀承担。多段配合 `SPREAD`，在「单体爆发」与「群体扩散」间取舍。

**持有状态**

- `block`：持有即生效的防御，是手牌作为「状态」的直接体现；高 `block` 配 `retain` 或不可出，构成常驻肉盾。
- `retain` / `ethereal`：决定一张牌在回合边界是「跨回合持有」还是「限时兑现」。
- `playable`：决定一张牌是「选择」还是「状态」。关时，或借其他字段转为持有期收益，或让「不可出」本身成为代价。

**行动与指向**

- `exhaust`：整场一次，还是可循环复用。
- `transferable`：把牌变成可传递载体——传敌投递负面、传友分发增益，方向由词缀决定；目标经 `target_type` 解析，可显式选择自身或直接用 `target_type=SELF` 实现「自传递复制」。副本**只传一跳**（落地即 `transferable=False`），收到副本者不能再次转手。
- `target_type`：作用对象由目标类型决定——`SINGLE` 单个、`ALL` 阵营全体、`SPREAD` 阵营散射、`SELF` 锁定自身（无需传入目标）。

## 词缀设计

词缀是唯一的语义自由度，也是「状态」的载体。全部写法硬边界（结算原语、数值限制、格式与非法置空）随生成契约的 `submit_card` 工具 schema 下发，每个原型的引导方向见其 `design` 字段（见下文「生成契约」），本节只讲方法：

- **先定时机**：`on_play` 出牌瞬时、`on_hit` 被命中时、`on_turn_end` 每次 pass turn（效果目标恒为当前持有者）、`on_autonomous` 每次 pass turn 的回合结束之后（效果目标为场上任意存活角色，是「卡牌作为自主主体」的时机）——时机只决定「何时兑现」，不决定语义；同一时机要同时考虑对持有者的增益与减益。
- **再做变量**：在骨架给定、且仲裁会全量给出的内建数值里（本卡字段、目标 / 自身的 `HP`、`总格挡`）选一个或组合当变量，把规则落成一句具体描述——「借哪个数值、怎么组合」就是词缀的自由度所在。

## 生成契约（`card_design` 引擎）

所有「让 agent 造一张卡」的路径共用同一套契约（`systems/card_design.py`），不再各自注入全局规范：

- **选型**（`run_card_selection_session`）：agent 用 `list_card_prototypes` / `get_card_prototype` 浏览原型库，再用 `select_cards` 一次性提交恰好 N 个原型 id。
- **设计**（`run_card_design_session`）：引擎把选中原型物化为候选卡（换新 `uuid`、回填 `source`），agent 用 `submit_card`（按 `#N` 定位）逐卡提交 `name` / `description` / 可选数值微调 / 词缀，再 `finish_cards` 收尾。
- **词缀硬边界随工具契约下发**：只写 `HP`（伤害 / 反伤 / 吸血 / 治疗）或经 `transferable` 牌施加持续状态，不得写格挡 / 抽弃牌 / 能量 / 布尔标志，只能引用内建数值；每个槽**至多一条**词缀。`validate_affix_slot` 仍只守格式硬不变量，落地时不合法的槽整槽置空。
- **每个原型往哪个方向设计**由该原型的 `design` 字段（`【骨架】【字段】【设计】`）给出——这是唯一的「设计引导」来源。
- **计算端持有 `uuid`**：LLM 只看编号 `#N`，`uuid` 由引擎回填，避免内部标识泄漏进提示词。

四条路径分别组装自己的候选与去向：

| 路径 | 选型 | 设计 |
| --- | --- | --- |
| 候选奖励（spoils） | 系统随机抽 N 个原型 | `run_card_design_session` |
| 怪物牌库（deck） | `run_card_selection_session(size=5)` | 同上 |
| 消耗品工坊 | `run_card_selection_session(size=1)` | 同上（带材料上下文）|
| 装备工坊 | `run_card_selection_session(size=1)` | 同上（带材料上下文 + `speed` 扩展字段）|
