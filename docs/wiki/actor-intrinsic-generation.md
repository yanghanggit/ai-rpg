# 角色自持内容生成（Actor Intrinsic Generation）

## 意图

角色实体可作为 agent 生成「属于该角色自身」的持久内容——候选奖励卡、外观描述等。这类产物会跨场景长期留存、被反复阅读；而副本场景在通关后即被销毁，卡牌却会留在牌库与角色身上。因此取材必须收敛到角色内化的稳定身份：一旦把生成时刻的外部环境写进去，产物就会耦合于一个高易变、且注定消失的具体场景——换场后读来突兀，场景销毁后更会指向一个已不存在的东西。

「外部信息污染」正是指这条路径：角色的 agent 记忆里天然带着当前场景的环境叙事、在场者与刚发生的遭遇，这些对扮演是必要的；生成任务若不显式划界，就会把易变信息一并沉淀进本应稳定的产物。

## 设计原则

- **取材边界**：只允许来自角色的系统设定——历史、性格、禁忌、最爱、体型，以及由此衍生的技艺、习惯与典故。
- **显式排除**：任务提示词须明文禁止引用当前场景、地点、环境、同行者与具体遭遇，并要求产物换到任何场景都成立。
- **引用完整性**：产物比场景活得久——卡牌跨副本留存，房间通关即销毁；因此禁止引用会先于产物消失的实体。判据是「通用指代 vs 具体实例」，而非「能否提到场景」：
  - 可以保留：目标、场上的敌人、持有者，以及角色自己世界里稳定的地理与文化（北地人的「北地的雪」）。
  - 必须排除：这间屋子的吊灯、那头跛脚的狼、刚塌的那面墙、当前副本的地点与在场者。
- **场景在记忆中不可避免**：角色记忆本就包含当前场景感知（扮演必需），要隔离的是「生成时对场景的引用」，而非场景本身；共享记忆不会自动过滤，必须由提示词显式约束。
- **概率性目标**：场景无关依赖 LLM 对提示词的遵守，接受其不精确；不引入确定性的场景词拦截，以免误伤本就可能内化的同形意象。

## 应用

- 候选奖励卡生成：从卡牌原型继承骨架字段与设计引导，角色自行设计 `name`/`description` 与词缀；词缀的格式与约束随生成契约（`submit_card` 工具的 schema）下发，每张原型的引导方向见其 `design` 字段，不合法的槽整槽置空。
  → 参见：[卡牌数据模型（Card）](card.md)、[卡牌设计指南（Card Design）](card-design.md)
- 外观合成：以角色基础体型为底，叠加时装覆盖，得到与着装状态一致的描述；未被遮挡的体貌细节须保留。实现上不在角色上下文里做，而是委托给世界实体「世界.外观合成」：只送该实体的规则与任务数据，不读也不写角色记忆，角色侧只拿到一条自我状态说明。
  → 参见：[战役设定与全局规则](campaign-setting-rules-bridge.md)
