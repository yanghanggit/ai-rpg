# 卡牌设计指南（Card Design）

---

## 定位

面向内容作者，回答「**每个字段这样设计，可以被怎样玩**」——即设计方法论，而非字段定义或具体范例的副本。

为避免同一事实出现两处、日后还要裁决谁权威，本文**不复述**以下内容，只给原则与指向：

- 字段语义（每个字段是什么）→ [卡牌数据模型（Card）](card.md)
- 词缀格式与约束（怎样写才合法）→ `AFFIX_DESIGN_SPEC`（代码内单一来源）
- 具体组合范例（原型长什么样）→ `demo/card_skeletons.py`（骨架）与 `demo/card_prototypes.py`（原型类型 + 含教学元数据的注册表）

## 设计总原则

- 每个字段单一职责，玩法靠**组合**表达，不靠新增字段。
- **确定性骨架 + 语义词缀**：确定性字段让回合循环可运转，词缀提供自由规则；接受仲裁 LLM 解释带来的语义 / 数值偏差。
- 同一张牌有**两个身份**同时成立：作为手牌的「持有状态」与作为行动的「打出」。
- 原型是**引导**不是模板：原型固定定量骨架并给出方向，具体规则由角色 agent 实例化，一个原型可覆盖多个方向。

---

## 硬约束（布尔字段）

布尔字段并非都能自由组合，以下三条在生成与手写内容中都必须遵守：

- `retain` 与 `ethereal` 互斥：二者同属「回合边界手中牌去向」这一语义轴的两极，同开会令 ethereal 先生效、retain 沦为死开关。
- `transferable` 与 `exhaust` 设 true 的前提是 `playable=true`：牌不可出时二者永不触发，属无效组合。
- `self_target` 与 `transferable` 互斥（**模型层硬拦截**）：`self_target` 锁定自身并跳过目标解析，`transferable` 依赖解析出的目标列表分发副本，二者语义冲突。若要「自传递复制」，请把 `target_type` 设为 `SINGLE` 并显式选择自身为目标——这是允许的玩法，与互斥字段无关。

---

## 字段速览

只给「设计含义」；取值语义见卡牌数据模型。

**资源与节奏**

- `cost`：出牌门槛，决定节奏与「出还是过」的取舍；只在出牌时刻收门槛，不影响能否留手。低费=稳定可循环，高费=爆发 / 终结。
- `damage` / `hit_count`：输出的强度与形态；`damage=0` 时价值改由 `block` 或词缀承担。多段配合 `SPREAD`，在「单体爆发」与「群体扩散」间取舍。

**持有状态**

- `block`：持有即生效的防御，是手牌作为「状态」的直接体现；高 `block` 配 `retain` 或不可出，构成常驻肉盾。
- `retain` / `ethereal`：决定一张牌在回合边界是「跨回合持有」还是「限时兑现」。
- `playable`：决定一张牌是「选择」还是「状态」。关时，或借其他字段转为持有期收益，或让「不可出」本身成为代价。

**行动与指向**

- `exhaust`：整场一次，还是可循环复用。
- `transferable`：把牌变成可传递载体——传敌投递负面、传友分发增益，方向由词缀决定；目标经 `target_type` 解析，可显式选择自身实现「自传递复制」，但与 `self_target=True` 互斥。
- `self_target` / `target_type`：作用对象是锁定自身，还是按目标类型（单体 / 阵营全体 / 阵营散射）。

---

## 词缀设计

词缀是唯一的语义自由度，也是「状态」的载体。全部写法边界（结算原语、数值限制、格式、原型引导与非法置空）以 `AFFIX_DESIGN_SPEC` 为唯一来源，本节只讲方法：

- **先定时机**：`on_play` 出牌瞬时、`on_hit` 被命中时、`on_turn_end` 每次 pass turn（效果目标恒为当前持有者）——时机只决定「何时兑现」，不决定语义；同一时机要同时考虑对持有者的增益与减益。
- **再做变量**：在骨架给定、且仲裁会全量给出的内建数值里（本卡字段、目标 / 自身的 `HP`、`总格挡`）选一个或组合当变量，把规则落成一句具体描述——「借哪个数值、怎么组合」就是词缀的自由度所在。
