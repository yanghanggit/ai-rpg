# 消耗品系统（ConsumableItem）

---

## 定位

消耗品是战斗中可主动使用的**队伍级**道具：库存统一由 player 持有（团队背包），使用动作则挂在「当前行动的我方角色」上——谁轮到自己回合，谁发起使用。

使用**不消耗 energy、不推进回合，且无使用次数限制**（`consumable_use_count` 仅是回合记录字段，供战斗日志与历史回顾展示）。是否轮到下一角色完全由过牌（pass turn）决定。

---

## 战斗使用管道

消耗品使用经过两个串联系统：

**前置系统**从团队背包（player 的 `InventoryComponent`）扣减库存（count 递减、归零移除），并向场景内所有存活角色广播使用通知。

**仲裁系统**借世界实体「世界.消耗品仲裁」作为临时 agent（LLM）结算 HP 变化：读取发起者与目标属性 → 依修正规则结算 → 写入 HP → 提交战斗日志/叙事。临时 agent 的对话上下文仅在本次结算过程中累积，不写回宿主世界实体的持久记忆；仲裁结果写入场景实体记忆并广播给全场。

> 权限边界：消耗品仲裁者不是场景本身，不读也不写场景环境快照（`EnvironmentComponent`）。它只把「发生了什么」写入场景实体记忆，由场景依自身上下文维护对环境状态的认知。

→ 参见：[装备系统（GearItem）](gear-item.md)（同为队伍级道具，但装备物化为手牌而非直接结算）

---

## 修正规则（modifiers）

`ConsumableItem` 携带 `modifiers`（字符多值列表）：每个元素是一条完整、独立的修正规则，用一句话说清「对谁、造成什么、数值多少」；本次使用仲裁会将所有元素**逐条全部结算**，一并注入临时仲裁 agent。

该字段与神器 `Artifact.modifiers` **同名、同语义**（原 `on_use_prompt` 已更名）：都是交给临时仲裁 agent 的输入提示词。agent 依「自己有哪些工具 + 输入状态」自主解释执行，边界的唯一定义就是**工具能解释什么**。生成侧受能力边界约束：只可描述「对目标（或发起者）造成伤害 / 恢复 HP」这类能被工具解释的即时效果，可用感官描写暗示表现方式；禁止状态效果、属性增减、道具增减、跨回合持续效果等工具无法解释的机制。

效果细节**刻意**留给 agent 裁定：卡牌有共享的结算模型（`CALC_RULES_SECTION`：per-segment 减总格挡、净伤害扣血），消耗品没有——例如「伤害是否减目标总格挡」由临时 agent 依输入自行判断（实测 `震击卷轴` 对总格挡 4 的目标仍完整打出 3 点）。这是设计上的自由，只要工具能解释即成立，不是缺陷。

---

## 合成来源

消耗品可由工坊系统从材料合成，命名遵循「消耗品.XXXX」约定；LLM 根据材料名称与描述推断产出并同步生成 `modifiers`。

合成产出入库时按堆叠身份合并：仅当与库存中既有条目「同名且修正规则一致」时并入该堆叠、数量累加，否则作为新条目追加。设计意图是让一次合成对应「一份」，重复合成同一产物表现为库存份数增长，而非同名条目堆积。堆叠身份依赖 LLM 生成的名字与修正规则，二者任一措辞变化即视为不同道具、不会合并；初始播种也可直接写入多于一件的堆叠。

→ 参见：[材料系统（MaterialItem）](material-item.md)（合成管道与材料消耗规则）
