# 公共知识检索系统（RAG）

## 定位

RAG 系统为 AI 角色提供「向世界提问」的能力。角色在行动规划中发起知识库检索，以自然语言从 pgvector 向量数据库检索该游戏世界的公共知识；检索结果作为工具消息即时回流，供角色据此提交行动决策。

核心设计决策是公共记忆与私人记忆的二元分离：`Blueprint.knowledge_base` 承载任何路人都可观察到的客观环境事实，经向量化存入 pgvector；角色的身世、性格、秘密等私人知识由各自 `profile` 字段承载，不进入向量库。二者互不污染——角色不知道的事，不能通过 RAG「顺便知道」。

## 知识库内容的编排约束

`knowledge_base` 是 `Dict[str, List[str]]`，key 为分类名，value 为该分类下的文档条目。内容编排遵循严格约束：仅写入感官层面的客观环境事实（建筑外观、气味、声音）；禁止人物信息、解释性判断、阵营立场、叙事秘密。单蓝图条目数控制在 5 条以内，控制 RAG 检索噪声。

这些约束服务于同一目标：公共知识库必须中立、紧凑，既不泄露叙事秘密，也不污染角色的独立认知。如果一条信息需要「特定身份」或「特定认知阶段」才能知晓，它就不该出现在这里。

## 两阶段生命周期

初始化阶段由开发环境初始化流程执行：读取蓝图目录下所有蓝图文件，将每个蓝图的 `knowledge_base` 展开为 `(document, metadata)` 二元组——metadata 记录 `category`。使用全局共享的 SentenceTransformer 实例向量化后存入 `vector_documents` 表，余弦相似度度量。每个游戏拥有独立 `collection`（以游戏名命名的列值），实现多世界向量空间隔离。`vector_documents` 表随 PostgreSQL 数据库在开发环境初始化阶段一并重建，保证每次重建为干净状态。

运行时阶段由家园规划系统的 `query_knowledge_base` 工具驱动：角色在 agentic 循环中调用该工具，问题向量化后在当前游戏 `collection` 中执行语义搜索，返回最相关的前若干条结果。检索在独立线程执行以避免阻塞事件循环；结果以工具消息形式回到循环，角色据此提交后续行动。pgvector 原生的余弦距离在检索层被转换为 [0, 1] 区间的相似度分数。

## 查询工具的触发与消费

`query_knowledge_base` 是角色规划循环中的可选工具：非强制、可多次调用，检索结果即时回流、解释权交给调用角色。相比旧 `QueryAction` 组件链路——检索在决策后旁路注入、下一轮才可见——新设计使检索成为决策的依赖前置：角色先查后答，本轮即可采信结果。

## 提示词分层

检索行为的引导分布在两层：

- 宪法层（`RPG_SYSTEM_RULES`）：不提及检索工具，仅声明「世界的公共事实不由角色编造，需从外部知识库获取」。
- 任务层（家园规划提示词）：告知可先检索再提交行动，检索可与任意行动叠加。

分层的意图：系统提示词是角色的「世界观宪法」，不出现具体行动机制；行动机制留给每轮的任务提示词按需告知。

## 相似度分数作为元信息

检索结果中内嵌相似度阈值指南（>0.70 高度相关 / 0.55–0.70 中等 / <0.55 低相关），引导 AI 自行判断是否采信，系统不做硬性过滤。空结果同样返回明确声明，让 AI 知晓检索已完成而非卡住。

## 跨系统关联

- `Blueprint.knowledge_base` 是数据定义端，开发环境初始化流程是数据加载端，`query_knowledge_base` 工具是数据消费端，三者构成「定义 → 向量化 → 检索」完整链路。
- 知识检索模块（`rag`）提供纯工具层：批量向量化写入与按 `collection` 过滤的语义搜索，桥接 SentenceTransformer 与 pgvector，不感知游戏业务逻辑。
- 消费端由家园规划系统承载 → 参见：[家园规划系统（Home Plan Action）](home-plan-action.md)
- 检索产出的工具消息与角色 profile、场景描述等一同进入 LLM 消息历史，影响角色的后续行动决策。
