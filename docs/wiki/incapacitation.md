# NPC 失能（Incapacitation）

## 定位

失能是剩余生命数（`lives`）耗尽后的终态：角色永久丧失**行动发起**与**信息摄入**两种能力，但实体保留。叙事上对应「深潜行动失败造成的永久脑损伤」——角色仍在世界里，只是不再思考、不再行动、不再感知。

失能标记组件的命名与具体成因无关，因此可复用于眩晕、瘫痪、永久沉寂等各种「失去行动力」的情形，而不仅限于本叙事。

## 设计决策

### lives：累积的战败惩罚

剩余生命数记录在角色核心属性上，初始为正整数，下限为零。战死、超时判负、撤退都计为一次战败，每次扣一。扣减集中在统一的死亡标记入口，而非散落在各条战败路径各自处理——这是为了让「何种结局算一次战败」只有一个定义点，避免不同路径口径漂移。

### 彻底失能 = 不行动 + 不感知

失能不是一种可被驱散的负面状态，而是一条不可逆的双向封禁，必须同时切断两件事：

- **行动发起**：角色不再产出任何行动。规划系统在过滤阶段就排除失能者，因此即使有外力强行挂上规划信号，也不会转化为行动。
- **信息摄入**：角色不再接收任何事件、不再写入记忆。事件通知入口跳过失能者，而记忆写入原语对失能者直接断言失败。

两者缺一不可。只停行动不停信息，角色会在记忆里继续积累，一旦未来有任何恢复可能就会行为错乱；只停信息不停行动，角色会在无信息状态下胡乱决策。把「行动」与「感知」当作同一枚硬币的两面，是失能语义的核心。

### 触发时机与记忆收束

失能判定只发生在**家园流程**，且位于规划系统之前。触发时先压缩角色记忆为一条摘要（复用上下文压缩的减负机制），再挂载失能标记——记忆被收束为「最后的自我」，此后不再增长。

选择家园作为判定点，是因为战败发生在副本，而失能作为一段旅程的**结果**，需要在角色回到生活场景时才正式落定。判定点先于规划，保证同一轮里失能者不会再被规划。

### 实体保留

失能不清除实体，也不清除身份。实体继续存在于场景中（可见、可被引用），只是引擎保证任何系统都不得再为其发起行动或写入信息。这使得「失能」与「死亡/销毁」成为两个正交概念：死亡是战斗内的临时出局标记，失能是跨副本的永久终态。

## 跨系统关联

- **战败扣减**：副本内的战死 / 超时判负 / 撤退经由统一的死亡标记入口扣减 `lives` → 参见：[战斗管道（Combat Pipeline）](combat-pipeline.md)
- **失能触发**：家园流程中位于规划系统之前的失能系统，压缩记忆后挂载失能标记 → 参见：[家园规划系统（Home Plan Action）](home-plan-action.md)
- **记忆收束**：失能时的记忆压缩复用上下文压缩这一减负手段 → 参见：[上下文窗口管理（Context Window Management）](context-window-management.md)
- **下游闸口**：队伍名单增删、副本进入、外观（穿/脱装）、行动计划激活、事件通知与记忆写入——全部拒绝失能者，构成「彻底失能」的落地约束。批量行动计划激活是「全量角色」的入口，**只要列表里含一个失能者就整单拒绝**，因此客户端必须先过滤掉失能者再发起推进。
- **外部观测**：服务器状态摘要暴露失能标记与剩余生命，供远程代理据此规避不可用角色 → 参见：[AI 代理 API 走查 CLI（ai-rpg-agent-api）](run-agent-api.md)
