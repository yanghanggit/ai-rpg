# 战役设定与全局规则桥接（CAMPAIGN_SETTING / RPG_SYSTEM_RULES）

## 设计意图

世界知识被刻意拆成两层，分别注入每个实体的 system prompt：

- `RPG_SYSTEM_RULES`：跨故事固化的引擎规则（角色扮演契约、副本定义、场景移动、战斗机制），对所有故事成立，保持不动。
- `CAMPAIGN_SETTING`：仅目标故事生效的动态设定（时代锚点、类型标签、副本的梦境语义），是全部实体的最低公共知识。

拆分的动机是机制与内容解耦：引擎只描述「场景移动是叙事跳跃」这类不变事实，故事只在设定层声明自己的语义（如「进出副本即入梦与醒来」），无需触碰引擎。

## 关键经验：抽象设定是惰性知识

仅把故事语义写进 `CAMPAIGN_SETTING`，不足以让 LLM 在扮演中稳定体现。实测中，NPC 的内心独白能采纳该语义，但公开对话仍退回物理叙事，且出现过对话目标路由错误。

根因是「触发缺口」：副本进出事件发生时，通知文案本身不带任何故事语义，LLM 就近采信这条具体信息，不会自发回读 system prompt 中远置的抽象设定。

## 桥接方案：事件级引用提示

在副本生命周期通知（进入 / 推进 / 退出 / 撤退）追加一句通用引用，把事件时刻的 LLM 指回自身 system prompt：关于副本及进出副本的设定，见你的「游戏设定」与「全局规则」。

该句不含任何故事专属内容，故不破坏解耦架构——语义仍只存于 `CAMPAIGN_SETTING`，通知只负责在事件发生时触发回读。实测此组合下，NPC 的内心独白与公开对话均稳定输出故事语义，且对话目标正确。

## 设计准则

- 故事语义只进 `CAMPAIGN_SETTING`，不进 `RPG_SYSTEM_RULES`。
- 需要在事件发生时被想起的故事语义，应在事件通知中放通用引用，而非把故事内容写进通知。
- 通知文案保持通用；引擎代码不应被具体故事语义污染。
