# 消耗品系统（ConsumableItem）

---

## 定位

消耗品是战斗中可主动使用的**队伍级**道具：库存统一由 player 持有（团队背包），使用动作则挂在「当前行动的我方角色」上——谁轮到自己回合，谁发起使用。

使用**不消耗 energy、不推进回合，且无使用次数限制**（`consumable_use_count` 仅是回合记录字段，供战斗日志与历史回顾展示）。是否轮到下一角色完全由过牌（pass turn）决定。

---

## 战斗使用管道

消耗品使用经过两个串联系统：

**前置系统**从团队背包（player 的 `InventoryComponent`）扣减库存（count 递减、归零移除），并向场景内所有存活角色广播使用通知。

**仲裁系统**借世界实体「世界.消耗品仲裁」作为临时 agent（LLM）结算 HP 变化：读取发起者与目标属性 → 依效果提示结算 → 写入 HP → 提交战斗日志/叙事/场景快照。临时 agent 的对话上下文仅在本次结算过程中累积，不写回宿主世界实体的持久记忆；仲裁结果写入场景实体记忆并广播给全场。

→ 参见：[装备系统（GearItem）](gear-item.md)（同为队伍级道具，但装备转化为手牌而非直接结算）

---

## 使用效果提示词（on_use_prompt）

`ConsumableItem` 携带 `on_use_prompt`（字符串列表，当前仅用首条）：一句话说清「对谁、造成什么、数值多少」，是本次使用仲裁的完整效果提示，注入临时仲裁 agent。

该提示词由合成 LLM 生成，受能力边界约束：只可描述「对目标（或发起者）造成伤害 / 恢复 HP」这类能被结算 agent 解释的即时效果，可用感官描写暗示表现方式；禁止状态效果、属性增减、道具增减、跨回合持续效果等结算 agent 无法解释的机制。

---

## 合成来源

消耗品可由工坊系统从材料合成，命名遵循「消耗品.XXXX」约定；LLM 根据材料名称与描述推断产出并同步生成 `on_use_prompt`。

→ 参见：[材料系统（MaterialItem）](material-item.md)（合成管道与材料消耗规则）
