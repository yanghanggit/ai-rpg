# 上下文窗口管理（Context Window Management）

## 意图

角色与场景的 agent 记忆随回合单调累积，上行 prompt 持续膨胀，最终逼近模型上下文上限。系统用三种减量手段应对：写入精简提示词、单次循环结束即压缩（仅限地下城场景实体的仲裁）、阈值触发压缩；前两者按写入时机触发，后者以「上下文占比」为信号量化窗口占用并全局兜底。

## 精简提示词

`DeepSeekClient` 同时持有「发送给 LLM 的完整提示词」与「写入记忆的精简提示词」两个版本：上行请求用完整版，写回记忆用精简版，从而让后续轮次不再携带完整提示词；完整版仅作为消息附加字段留痕。

当前消费方是 `EnvironmentInitializationSystem`（环境叙事）与 `MonsterCombatDecisionSystem`（怪物出牌决策），二者都在批量调用后把精简版写入各自 agent 记忆。

## 阈值触发压缩

`DeepSeekClient` 在每次响应后计算本次 token 用量占模型上下文窗口的比例，随 AI 回复消息同步到 `AgentMemory`，作为「该 agent 上下文有多满」的信号；经存档持久化、恢复时回填，跨命令可读。

`ContextCompactionSystem` 挂在每条流程管线的收尾前，每轮遍历所有 agent，对占比超过设定阈值的 agent 触发压缩：保留首条 system 消息，其余全部压成一条第一人称摘要，并把占比重置回 0，等待下一轮真实调用重新累计。

该机制对所有 agent（含场景实体）一视同仁，是最后兜底的减量手段，与精简提示词互补：它按占比阈值全局触发，精简提示词按写入时机触发。

压缩只保留两类内容：首条 system prompt，以及显式声明「压缩时保留」的消息（目前唯一来源是仲裁循环未完成时的「本次未落库」说明）。因此绝大多数事实型记录（胜负、战利品、领取、阵亡）**只属叙事，允许被摘要吞掉**——它们的权威载体是组件，记忆只负责让人记得大概发生过什么。哪些事实即使压缩也必须留在记忆里取决于玩法，这条边界仍是暂定值，待玩法稳定后再逐项确认。

## 仲裁 loop 的逐次压缩（仅限地下城场景实体）

战斗仲裁把「一次 agent 循环」当作可耗材对待：循环结束后把整段轨迹（起始提示词 + 工具调用 + 工具回显）替换为一条总结消息，并给该消息打上起始/结束标记，供日后按标记反查区间；被替换的原文仅作为附加字段留痕，不再上行。这是「逐次压缩」（每次仲裁都做），与上文「阈值触发压缩」（全局、按占比）分层共存：局部保持上下文小，全局兜住任何遗漏。

只有以下四个仲裁系统享有这一待遇，且仲裁者恒为地下城场景实体：出牌、回合结束、自主运行、出牌后的神器修正。其余场景侧生成（环境叙事）为单轮无工具调用，本身不留轨迹；这是刻意的不对称。

关键在于作用域收敛：该策略只作用于地下城场景实体，而这些实体只在退出副本时统一销毁（通关后退出、主动退出、撤退后退出三条路径都经同一出口），其累积记忆一并消失；逐房间推进只切 `current_room_index`，不销毁已通过的场景。因此「战斗阶段压缩对话、剧情角色保留原貌」两种策略不会互相外溢：角色（玩家 / NPC / 怪物）与家园场景永远走「真实工具轨迹即记忆」，不会被战斗侧的压缩规则波及。

未完成的仲裁循环（模型未在轮次上限内提交、或循环抛错）不回滚、不删除：轨迹原样留在记忆里，另补一条系统说明声明「本次未落库」，并在回合日志留下一条失败记录。失败也是上下文的一部分，且让 agent 知道自己失败过，比抹掉痕迹更接近事实。该说明带有「压缩时保留」的标记，因此阈值触发压缩把其余内容折叠为摘要时，这些失败痕迹仍以原文留在摘要之后。
