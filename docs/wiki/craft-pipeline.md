# 工坊合成管道（Craft Pipeline）

---

## 设计意图

工坊合成系统的核心哲学是**机制与内容的彻底分离**。合成任务指令（prompt 模板）仅承载游戏框架层的规则约束——命名格式、卡牌字段边界、效果能力边界——这些由框架层定义且不随世界观变化。而故事世界观层面的内容（生态区域、文化风格、命名倾向）全部通过外部配置注入，不对 prompt 模板产生任何硬编码依赖。

这意味着：提供一套新的世界设定与材料列表，无需修改任何合成系统代码，即可生成风格完全不同的合成产物。

---

## 信息注入的两层架构

工坊 agent 每次调用 LLM 时，实际传递的信息由两个独立来源组合而成：

**系统消息（system_message）**：在蓝图 JSON 的 `world_entities` 中直接编写，包含战役设定、全局规则与工坊专属的角色规范。该消息作为实体 agent 记忆的第一条消息持久驻留，每次 LLM 调用时随 context 一同发送。

**任务提示（prompt）**：由各合成系统的 `_build_craft_*_prompt` 函数即时构建，仅包含本次合成的材料清单、输出 JSON schema 以及框架层的机制约束。模板中不出现任何世界观相关文本。

二者在 `DeepSeekClient` 内部会合为完整的 API 消息数组：context 中的消息在前，本轮 prompt 作为最新的 user 消息追加。

---

## 内容配置的注入路径

要将工坊适配到新的游戏世界观，需修改以下配置文件，合成系统代码无需变动：

- **战役设定与知识库**：蓝图 JSON 的 `campaign_setting` 与 `knowledge_base` 字段，定义世界的生态区域、历史背景、环境联动关系。该内容随各工坊世界实体的 `system_message` 注入。
- **工坊角色规范**：蓝图 JSON 中各工坊世界实体（`世界.装备工坊` / `世界.消耗品工坊` / `世界.时装工坊`）的 `system_message`，定义对应工坊的命名格式、描述约束、以及各自层面的感官风格指引。
- **初始材料池**：蓝图 JSON 的 `storage` 字段（初始储物箱）预置的 `MaterialItem` 列表，决定工坊的原料语义空间。材料的名称与描述是 LLM 推断合成产物的唯一内容线索，更换材料即更换产出风味。

---

## 三类合成产物

工坊系统支持三种合成方向，由发起合成时选定的产物类型决定走哪条管道：

- `ConsumableItem`：一次性战斗道具，携带 `on_use_prompt` 使用效果提示词，描述可被结算 agent 解释的即时效果（伤害/恢复 HP）。
- `GearItem`：装备道具，携带 `card_spec` 功能边界，战斗中转化为手牌、战斗结束归还。
- `CostumeItem`：纯外观道具，仅包含名称与描述，不参与任何战斗计算。

三者共用同一材料池，但 agent 已按职责拆分为三个世界实体：消耗品由「世界.消耗品工坊」（`ConsumableWorkshopComponent`）负责，装备由「世界.装备工坊」（`GearWorkshopComponent`）负责，时装由「世界.时装工坊」（`CostumeWorkshopComponent`）负责，仅 prompt 模板与产物 schema 因目标类型而异。各工坊的具体审美与内容约束由其 `system_message` 注入，不在此处展开。

## 材料驱动的创意生成

材料是 LLM 推断合成产物的唯一语义输入。prompt 模板将材料名称与描述逐一列出，LLM 据此推断：

- 合成物的名称、外观、手感或使用感受
- 产物的效果提示（消耗品）或卡牌功能边界（装备）
- 效果的叙事合理性（如毒蝶触须产生毒性效果、废旧皮革产生防护效果）

这种设计使材料描述的质量直接影响合成产物的个性化程度——描述越具体、越富感官细节，合成结果越具辨识度。这也是材料命名约定（`材料.XXX`）与产物命名约定（`消耗品.XXX` / `装备.XXX` / `时装.XXX`）统一使用前缀的核心原因：维持语义清晰度，便于 LLM 在推理时建立来源与产物的关联。
