# 上下文窗口管理（Context Window Management）

## 意图

角色与场景的 agent 记忆随回合单调累积，上行 prompt 持续膨胀，最终逼近模型上下文上限。系统用三种减量手段应对：写入精简提示词、战斗记忆归档、阈值触发压缩；其中阈值触发压缩以「上下文占比」为信号，量化当前窗口占用并据此兜底。

## 精简提示词

`DeepSeekClient` 同时持有「发送给 LLM 的完整提示词」与「写入记忆的精简提示词」两个版本：上行请求用完整版，写回记忆用精简版，从而让后续轮次不再携带完整提示词；完整版仅作为消息附加字段留痕。

当前消费方是 `StageDescriptionSystem`（场景描述）与 `MonsterPrePlaySystem`（怪物出牌决策），二者都在批量调用后把精简版写入各自 agent 记忆。

## 战斗记忆归档

`CombatArchiveSystem` 在战斗结束后触发：定位「战斗开始」与「战斗结束」两条标记消息，删除二者之间的整段逐条记录，改由 LLM 生成一段第一人称摘要，作为角色对这场战斗的唯一记忆；被删除的原文附在摘要消息上留痕。

## 阈值触发压缩

`DeepSeekClient` 在每次响应后计算本次 token 用量占模型上下文窗口的比例，随 AI 回复消息同步到 `AgentMemory`，作为「该 agent 上下文有多满」的信号；经存档持久化、恢复时回填，跨命令可读。

`ContextCompactionSystem` 挂在每条流程管线的收尾前，每轮遍历所有 agent，对占比超过设定阈值的 agent 触发压缩：保留首条 system 消息，其余全部压成一条第一人称摘要，并把占比重置回 0，等待下一轮真实调用重新累计。

该机制对所有 agent（含场景实体）一视同仁，是最后兜底的减量手段，与前两者互补：它按占比阈值全局触发，精简提示词按写入时机触发，战斗记忆归档按战斗结束触发。
