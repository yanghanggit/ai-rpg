# 卡牌数据模型（Card）

---

## 定位

`Card` 是战斗行动的最小单元。其字段按「谁来消费」分为三层：确定性骨架、语义词缀、生命周期流转。三层职责正交，共同决定一张牌在战斗中的行为。

→ 参见：[LLM 生成型游戏对象：Card](llm-generated-objects.md)（生成点与全局约束；本文只谈字段设计）

---

## 确定性骨架（计算端消费）

`name` / `description` / `cost` / `damage` / `hit_count` / `block` / `target_type` / `self_target` 构成牌的确定性底座。

`cost` 由出牌执行端扣减 energy；`damage` 与 `block` 在牌进入战斗牌堆时叠加角色攻击/防御，之后分别参与伤害结算与持有期防御；`target_type` 与 `self_target` 决定目标解析策略——单个目标、阵营锚点展开、阵营散射三种语义。

`name` 是标识与 LLM 决策的匹配键；`description` 是叙事锚点，只影响仲裁叙事演出，不改变确定性数值结算。

→ 参见：[卡牌关键词（keywords）](keywords.md)（数值与目标字段的约束来源）

---

## 语义词缀（LLM 仲裁消费）

三组词缀 `on_play_affixes` / `on_hit_affixes` / `on_turn_end_affixes` 是自由文本 `[名称]:触发倾向描述`，分别锚定出牌、被命中、回合结束三个触发时机。词缀由仲裁 LLM 结合牌面数值与场景状态解释执行，是玩法灵活性的主要来源。

出牌与受击并入出牌仲裁结算；回合结束词缀由独立仲裁在 pass turn 后对持卡人单独结算，且只结算持卡人自身的牌。

→ 参见：[战斗管道（Combat Pipeline）](combat-pipeline.md)（仲裁与词缀结算时机）

---

## 生命周期流转（计算端消费）

`playable` / `exhaust` / `retain` / `ethereal` / `transferable` 控制牌在牌堆间的确定性流转，每个标志单一职责、互不叠加语义：

- `playable`：不可出时在出牌执行端拦截。
- `exhaust`：出牌后永久离场，不进弃牌循环。
- `retain`：回合末保留，跨回合存续。
- `ethereal`：pass turn 时若仍在手牌则自动离场。
- `transferable`：出牌时从源手牌移除本体，并 copy 一份到每个解析目标的手牌（副本 uuid 重新生成）。

组合这些标志即可表达「一次性爆发」「常驻被动」「传染型持续效果」等玩法。

---

## source 的双重身份

`source` 记录牌的来源（生成/注入者名称）：初始牌库为角色自身，场景塞牌为场景实体。它首先是追溯手段；其次参与玩法语义——如回合结束词缀写「对非 source 者造成伤害」，仲裁 LLM 据此比较持有者与 `source` 判定目标，配合 `transferable` 实现「投掷到敌人身上后反噬对方」的传染机制（出牌时 copy 到敌方手牌，回合结束时由敌方持有）。

---

## 设计决策

分层的核心是「确定性骨架 + LLM 语义」：计算端只保留让回合循环可运转的最小确定性（目标、流转、能量、死亡），词缀解释与数值结算交给 LLM。这是游戏场景下的刻意取舍——接受偶尔的数值/语义偏差，以换取玩法灵活与低脚手架成本。
