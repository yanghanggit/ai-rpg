# 战斗管道（Combat Pipeline）

---

## 定位

战斗是一个以 `Combat` 状态机为核心的回合推进过程，由 ECS 处理器链按注册顺序驱动——顺序即因果链，无事件总线、无中心化状态机。战斗房间只是战斗的载体：它提供战场环境（stage）与参战角色（actors）；战斗本身是独立于房间的生命周期——**初始化 → 多回合累积推进（直到分出胜负）→ 结束**。

## 三阶段框架

### 初始化（仅一次）

把预置牌库确定性填入抽牌堆，为参战角色挂载空牌堆并注入战场环境，随后切换到进行中。卡牌在此第一次被获取：从 `DeckComponent` 进入 `DrawPileComponent`（按角色攻击/防御对伤害与格挡做叠加），尚未进手。

### 回合推进（循环，直到结果）

每回合内部是一条固定因果链：抽牌 → 出牌决策 → 动作执行 → 仲裁 → 死亡判定 → 回合完成 → 清理 → 胜负判定 → 下一回合。链由 `process()` 心跳驱动——系统按注册顺序执行、各自检查状态决定是否行动。胜负判定是唯一退出分支。

抽牌是回合的唯一入口：`DrawCardsAction` 触发时先创建新回合（无回合或上一回合已完成时），再完成全员抽牌，二者在同一处理周期内连续完成，一个回合每个存活参与者只抽一次。回合内出牌等行动均以抽牌完成为前置。抽牌是卡牌第二次被获取的时机：从 `DrawPileComponent` 进入 `HandComponent`（先取回保留牌，再尽量抓满目标张数；保留牌不占抓牌名额）。回合内装备物化、可传递牌转移也会改变手牌。

### 结束（仅一次）

掉落、战斗摘要归档、三堆牌副本清空、装备归还；`DeckComponent` 原始牌库完整保留。

## 回合（Round）与行动（turn）

`Round` 快照承载一个回合的推进状态，三个字段构成「行动权推进」机制：

- `action_order`：回合开始确定的行动顺序快照（按角色有效速度降序，速度相同按实体创建顺序升序；有效速度 = 基础 `speed` + 已装备件 `speed` 之和；本回合内不变），决定「谁先行动」。
- `current_actor`：当前应行动的角色，由「`action_order` 中第一个未过牌且未死亡」推导，是派生指针，不是独立状态。
- `completed_actors`：已过牌的角色列表，是行动权推进的唯一依据。

回合内的最小单位是**行动（turn）**：轮到某角色时，它可连续出牌、用消耗品、物化装备，直到它**过牌（pass turn）**。过牌是角色级动作——把该角色记入 `completed_actors`、把 `current_actor` 推进到下一位，只结束「这一个角色的行动窗口」。

## 过牌与回合结束是两个粒度

**过牌（pass turn）≠ 回合结束**：过牌只结束单个角色的行动窗口；当且仅当所有存活角色都已过牌，回合才完成，随后清理旧手牌、创建下一回合。能量耗尽只限制能打出的牌数，不自动过牌。

`on_turn_end_affixes`（回合结束词缀）结算于**持卡人每次 pass turn**，而非整回合结束——「回合结束」在此指「该持有者自己的行动窗口结束」，与「所有存活角色都过牌」是两个粒度。

→ 参见：[卡牌数据模型（Card）](card.md)、[手牌（HandComponent）](hand.md)

## 设计决策

### 牌库预置，抽牌堆确定性填充

初始牌库由角色蓝图预置卡牌直接写入 `DeckComponent`，战斗起始不调用 LLM；抽牌堆按角色攻击/防御对伤害与格挡做叠加后确定性填充。意图：牌库内容回归内容作者的确定性控制；属性叠加使同一张预置牌在不同角色身上呈现差异化强度。

### 仲裁的归属

仲裁按触发时机归属不同主体，而非统一由场景实体处理：

- 出牌仲裁由场景实体执行：它持有战场环境叙事与各角色 HP 变化通知，能产出叙事一致的结果；叙事只影响演出措辞，伤害仍按确定性规则结算。场景实体的环境快照已在战斗开始时注入其上下文（`CombatInitStageSystem`），战斗中的仲裁不再读写该组件。
- 回合结束词缀仲裁由持卡人执行，只结算其手牌中带回合结束词缀的牌，结果定向广播给受影响角色。归属持卡人而非场景实体：词缀是持有者自身的持续状态，结算视角应落在持有者。
- 消耗品仲裁由世界实体「世界.消耗品仲裁」作为临时 agent 执行，结算上下文不写回宿主记忆。
- 神器仲裁由场景实体作为仲裁者执行：神器与 `Card` 同级，是场景级战斗修正规则的载体，被 `ReliquaryComponent` 携带、且 `phases` 命中 `ArtifactPhase.POST_ARBITRATION` 的神器，会在出牌/消耗品仲裁后由所在场景结算；结算过程写入场景持久记忆，并通过广播使场上角色获得记忆。

> 环境快照：`EnvironmentComponent` 仅在初始化时由 `EnvironmentInitializationSystem` 写入一次。战斗中的各仲裁者（场景/神器、持卡人、消耗品）均**不读不写**该快照；它们只把「发生了什么」写入相关实体记忆，由各自后续推理依上下文维护对环境状态的认知。

→ 参见：[卡牌数据模型（Card）](card.md)、[消耗品系统（ConsumableItem）](consumable-item.md)、[神器（Artifact）](artifact.md)

### 多值文本字段逐条结算

卡牌三词缀（`on_play_affixes` / `on_hit_affixes` / `on_turn_end_affixes`）、神器与消耗品的 `modifiers` 都是**多值列表**：每个元素是一条完整、独立的规则。生成与填充侧统一清洗（去首尾空白、丢弃空项、按序去重），消费侧逐条分行注入并**逐条全部结算**——出牌、回合结束、怪物决策按词缀逐条渲染，消耗品仲裁把全部修正规则一并交给临时 agent；禁止用 `、` 之类的连接符把多条独立条目合并成一个整段字符串。

### 状态就是牌：没有独立状态存储

系统没有 buff / 标记组件，也无法通过仲裁器写除 `HP` 以外的状态：一个角色当前的「状态」= 其手牌中承载词缀的牌。给对方施加持续状态靠 `transferable`（副本进对方手牌，保留原 `source`），由该牌自带的 `on_hit_affixes` / `on_turn_end_affixes` 结算；出牌仲裁的 `get_entity_stats` 会把目标手牌中带 `on_hit_affixes` 的牌一次返回，作为可读状态面。**结构性效果**（抽牌 / 弃牌 / 移牌 / 能量 / 额外行动 / 改流转 flag）不在原语范围内，属骨架字段与数据流转系统；词缀若声明这类效果或凭空标记，不会被结算，会被仲裁器记入 `unsettled_affixes` 供 telemetry。

### 解释不了的词缀：让生成 agent 在提交前知道

「这条词缀能不能被解释」必须由**生成 agent 在提交前**判断：只有它握着完整上下文（词缀槽 + 结算原语 + 想表达的效果）。事后没人能补——牌库打磨结构上禁止改属性 / 词缀，仲裁时生成 agent 早已不存在。`AFFIX_DESIGN_SPEC`（「结算原语」硬边界 + 范围外「请改写或删除」）与 `validate_affix_slot`（只守格式硬不变量）就是这条分工。

`unsettled_affixes` 是**万一漏过时的兜底**，不是交接点：

- 它会将提交结果写进场景记忆（`.worlds/<user>/<game>/<ts>/memories/场景.*.jsonl`）并打一条 `logger.warning`；
- 但它**没有自动接收者**：生成 agent 在仲裁时已消失，牌又不能承载回执（打磨只允许改 `name` / `description`）；
- 所以把它当开发遥测去读日志 = 把静默失败留给开发者，正是本项目要消灭的失败模式。

排查命令（字段嵌在被转义的 JSON 字符串里，故模式需带 `\\"`）：

```bash
grep -rho 'unsettled_affixes\\": \[[^]]*\]' .worlds --include='*.jsonl' | grep -v '\[\]'
```

> 观测记录：截至当前全部存档（3003 个记忆文件、89 条仲裁提交），非空 **0 条**、日志 warning **0 条**——与「生成期自检有效」一致。

### 仲裁数值来源唯一性

仲裁结算的数值以系统给出的角色状态为唯一来源：**总格挡**（角色级＝其手牌 `block` 之和）已聚合完成，LLM 必须直接采用，不得再叠加单牌 `block`，也不得从对话历史或前几回合广播中补算卡牌与数值。该约束用于阻断 LLM 把历史回合出现过、当前并不持有的卡牌误植回本次结算，也用于区分「总格挡」（角色级）与「单牌格挡」（`block` 字段）。

### 伤害落实与回填一致性

仲裁把「算」与「写」都交给 LLM（`set_entity_hp` 写最终值、`submit_arbitration` 提交日志），因此存在一类**推理-执行脱节**的已知失败模式：算出了有效伤害，却没有把它从当前 HP 中扣除。典型形态是 LLM 自造「未破防 / 伤害被格挡大半」的理由，把 HP 记为不变。

为收敛该风险，`arbitration_prompt_builders.py` 的 `CALC_RULES_SECTION`（出牌/回合结束仲裁共用）明确：

- **结算公式**：`净伤害 = 基础段之和 + 词缀段之和`——基础段为 `hit_count` 段、每段 `max(0, 本卡 damage − 该目标总格挡)`（**每段各减一次总格挡**），词缀段为本卡每条词缀各自追加的伤害 / 格挡（不过总格挡）；`最终 HP = clamp(当前 HP − 净伤害, 0, 最大 HP)`；
- 只要净伤害 > 0，HP 就必须减少；不存在「未破防 / 低于阈值不扣血」，只有净伤害恰为 0 时 HP 才不变；
- **只有“净伤害”能用来扣血**——`damage × hit_count + 词缀追加` 这个未减总格挡的原始和不是扣血量；
- 词缀逐条成项。不可漏；数值只取本次 `get_entity_stats`；
- **回填一致性**：combat_log 的「伤害 Z」必须等于目标 HP 的减少量（旧−新）；`set_entity_hp` 的返回会回显 `旧 → 新（本次扣减 Z）`，日志须逐字抄它；对不上即算错；
- 附「部分格挡」算例作为锚点。

**负例（真实事故）**：`基础攻击`（damage=5, hit_count=1）攻击 `头狼`（HP 2/10, 总格挡 4）。正确结算为 `max(0,5−4)=1`、`HP 2→1`；实际却提交 `set_entity_hp 头狼 = 2` 与 `HP:头狼 2→2（5伤害−4格挡＝1，未破防）`——日志内部自相矛盾（声称伤害 1、HP 却不变），并用一个规则中不存在的「未破防」自圆。该缺口当时无任何代码校验拦截，是纯提示词层面的漏洞。

> 设计取舍：本项目不在代码层为仲裁数值加护栏（避免用确定性的天花板压掉 affixes / modifiers 的泛化空间），而是把规则与算例写全，让 LLM 在明确规则内推理；代价是此类错误率降低但不归零。

### 仲裁方差（观测记录）

同一战斗快照重放 `装备.旧铁剑`（`damage=7`、`[劈砍]:额外结算本卡 damage×1`、目标 `头狼` `总格挡=2`、`hit_count=1`）。经提示词结构收敛（本卡数据与词缀分段、`get_entity_stats` 按实体分块、`set_entity_hp` 回显 `旧 → 新（本次扣减 Z）`、日志逐字抄它）后：

- **词缀漏结算**（未追加 `[劈砍]`）：已消除。
- **跨实体格挡混用**（用出牌者自己的总格挡代替目标的）：已消除——`CALC_RULES_SECTION` 与 `get_entity_stats` 统一命名为「总格挡」并标注「结算伤害时只减这个数」。
- **回填不一致**（log 的「伤害 Z」与 `set_entity_hp` 的旧→新对不上）：已消除——`set_entity_hp` 的返回回显 `旧 → 新（本次扣减 Z）`，日志逐字抄它，不再两次独立心算。
- **残留（约 10%–15%，重放实测 13/15 正确）**：把 `damage × hit_count + 词缀追加` 这一**未减总格挡的原始和**当成扣血量（应先在基础段里减掉总格挡）。已加「只有净伤害能扣血，未减总格挡的原始和不是扣血量」的显式约束，仍未归零。

> **已结案——作为已知残余挂着**：采样温度默认 1.0，此类多步算术必然存在采样抖动；提示词层的结构重排、命名统一、回显绑定、显式消歧等手段已用尽，再加码收益递减（唯一未试的一招是「禁止列出原始和」，但有反噬风险）。决定不去动它——**不为仲裁数值加代码护栏，也不降温度**；要归零只能靠这两条已被否决的路径。

### 决策与结算分离

出牌分决策与仲裁两步：决策并行（各行动者同时选牌选目标），仲裁单线程（叙事一致），决策 LLM 不受仲裁风格干扰。怪物决策由 `MonsterPrePlaySystem` 用角色自身记忆完成，`PartyPrePlaySystem` 与怪物侧对齐结构。

一次怪物行动只产出一张牌决策（选一张牌或过牌），不存在连打多张。怪物决策采用「提示词预防 + 决策兜底」双层防护：只暴露费用可支付的牌并引导能量不足时过牌；即便选错，也在生成出牌动作前拦截、强制过牌，保证错误决策不进入结算。

怪物决策的对手视图遵循「模糊总量 + 相关点亮」：每个对手只暴露 `HP`、`总格挡`（手牌 `block` 之和，持有即生效）与 `手牌总数`（一个整数），并在此总数中点亮两类牌——带受击词缀（`on_hit_affixes`）的牌，或来源为本怪物（`source` 等于怪物名）的牌。前者让怪物权衡「命中该对手会触发什么反制」，后者让怪物看到自己投递进对手手牌的牌（配合 `transferable` 副本保留原 `source` 反噬）。其余手牌保持隐藏。
